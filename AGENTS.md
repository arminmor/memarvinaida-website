## Project

**memarvinaida-website** is a memorial site built with Next.js 16, React 19, and TypeScript. Single-page personal site with photo gallery and multi-language support (English, Farsi).

## Tech Stack

- **Next.js 16.3.1**: App Router (not Pages Router)
- **React 19.2.8**: Server Components by default; use `"use client"` for client-side features
- **TypeScript 5**: Strict mode enabled
- **ESLint 9**: Config-based linting
- **CSS**: Global styles in `app/globals.css`, component-scoped styling via inline styles or CSS modules

## Code Conventions

- **Server Components**: Default for all components; only add `"use client"` when needed (interactivity, hooks, event handlers)
- **File naming**: PascalCase for React components (e.g., `MemorialPage.tsx`), lowercase for routes/utilities
- **Exports**: Named exports for components and utilities; default exports only for pages/layout
- **Styling**: Prefer inline `style` props for component-level styles; use `globals.css` for document-level rules
- **Types**: Define interfaces/types at the top of files; use TypeScript for all `.ts` and `.tsx` files

## File Structure

- `app/`: Next.js App Router directory
  - `layout.tsx`: Root layout with metadata, SEO, and global providers
  - `page.tsx`: Home page (entry point)
  - `MemorialPage.tsx`: Main memorial component with gallery and content
  - `globals.css`: Global styles (reset, typography, theme)
- `lib/`: Shared utilities (helper functions, constants, types)
- `public/`: Static assets (images, fonts, favicon)

## Development Workflow

- **Branch**: `/feature "description"` creates appropriately-prefixed branch (feature/, fix/, refactor/, etc.)
- **Local dev**: `npm run dev` starts the dev server at http://localhost:3000
- **Type checking**: TypeScript runs automatically; fix errors before committing
- **Linting**: `npm run lint` checks code style
- **Build**: `npm run build` creates a production build in `.next/`
- **Preview**: `npm start` runs the production build locally
- **Commit**: `/commit <message>` stages and commits changes with clear messaging
- **Push**: `/push` sends commits to remote branch

## Important Notes

- **Client hydration**: Ensure Server/Client component boundaries are clear to avoid hydration mismatches
- **Images**: Use Next.js `<Image>` component for optimization when possible
- **Environment variables**: Place in `.env.local` (not in git); reference as `process.env.NEXT_PUBLIC_*` in the browser
- **Commits**: The AGENTS.md file is auto-generated by `next dev` — keep the XML comment blocks intact; add new guidance outside them
